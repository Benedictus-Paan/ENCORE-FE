# Audit Reports

Create a new Markdown report for each task that changes application code, configuration, dependencies, tests, or project documentation.

## Naming
Use a readable sequential or date-based filename, for example:
- `001-event-list-filters.md`
- `2026-10-16-artist-staff-management.md`

Never overwrite an earlier report. Add the report to an index here if the project uses an index.

## Report requirements
Copy `TEMPLATE.md` and document:
- Request and changes made
- Why this approach fits the project
- Beginner-friendly explanation of the relevant code/data flow
- Checks actually run and real results
- Risks, limitations, and follow-up work

For analysis-only tasks, create a report only when the task scope or project conventions require it. Never claim code changed when it did not.
